# LA3 原生策略的补边颜色／操作顺序 CPU 审计

日期：2026-10-29 UTC。结论范围：公开源码、发布策略、确定性合成图像；没有训练、真实数据、预训练权重或泛化测量。

**窄像素机制成立，但当前进入训练的门未通过。** 原生发布策略确有 Identity＋Invert＋单几何三元组，执行顺序没有被随机打乱。当前 Pillow 环境下几何操作使用 nearest 和黑色补边，交换 Invert 与几何操作能保持源像素完全相同，并把补边从 0 改成 255。然而，同一语义变换条件下的跨类顺序差异只在 ImageNet 的 7 条策略条目中出现；预先定义的全图 L2 严重度相等条件在全部非零主门干预中失败。不能据此称 LA3 有泛化缺陷、已有贡献，或宣称这条机制无效。

## 1. 原生实现与版本

- 作者仓库固定提交：[`3e593946980912524fb167dad00e83b1b08ec16e`](https://github.com/Simpleple/LA3-Label-Aware-AutoAugment/tree/3e593946980912524fb167dad00e83b1b08ec16e)，提交树 `8f6f02cbbdc3a9970a8cfd4d63c9216ceead62e3`。源码和策略均验证 Git blob SHA-1 与 SHA-256，见 `sources/` 中各 manifest。
- 论文使用 [LA3 arXiv:2304.10310v1](https://arxiv.org/abs/2304.10310v1)，PDF 16 页，作者 Mingjun Zhao、Shan Lu、Zixuan Wang、Xiaoli Wang、Di Niu，论文标注 ECCV 2022，arXiv 提交于 2023-04-20。本文不把 arXiv 上传年份误写成会议年份。
- 三个发布策略文件每类均有 **101 个条目**，不是论文 PDF 第 10 页名义的 100。统计采用实际 101。源码 `search_stage_2.py:146–163,274–280` 从一个已选条目开始，再追加 N 项，可解释 101 的实现来源；没有重新执行搜索，不能独立证明发布策略的生成历史。
- `LA3/data.py:535–552` 均匀抽取一条三元组，按存储的三个位置依次执行。每个操作独立抽取 `random.choice(range(10)) / 10`，无另一个随机开关概率。Invert、Identity 也消费幅度抽样，但其操作忽略幅度。
- `LA3/augmentations.py:12–60,163–180,200–202`：Shear 范围 ±0.3；Translate 范围 ±0.45 倍对应图像尺寸；Rotate 范围 ±30°。十个幅度先线性映射到 `[−a,−0.8a,…,0.8a]`，几何符号再以 0.5 概率翻转，故正负端点各质量 0.05、零值质量 0.1。操作之间的幅度、符号随机数独立。
- 几何函数没有传 `resample` 或 `fillcolor`。本次 Pillow **13.0.0** 实测为 **NEAREST、RGB (0,0,0)**。未改成人为黑白实验；255 是原生黑色被 Invert 后产生的结果。若其他实现采用 fill=128，则同一推导只能产生 127/128，不能借本报告放大成黑白。原仓库未锁定 Pillow 版本，因此不声称历史训练环境逐像素复现。
- Cutout 是另一通道：`augmentations.py:125–147` 使用 RGB `(125,123,114)`，不能与几何补边混为一谈。
- 预测器在 `networks/neural_predictor_model.py:160–170` 把三个操作 embedding 相加；这使其表示不区分排列，**不代表执行顺序被随机化**。该事实本身不是新颖性结论。

复核：额外直接执行作者 `PDA_Aug_Policies_Op` 类定义，以相同真实类策略和 RNG 对照参数记录回放，共 **168 次，最大像素误差 0**。只提取经检查的类／函数 AST，未导入或运行训练入口。交换时参数跟随操作实例；未用“两个分支重设同一 seed”替代随机数配对。

## 2. 事件频率与条件支持

主门严格限定三个不同操作：Identity、Invert、一个几何操作。下面是**均匀抽类、类内均匀抽策略条目**的精确策略质量，不是实测训练事件频率。几何零幅度、取整、后续裁剪／Cutout 还可能使可见事件消失。

| 发布策略 | 总条目 | 主门条目／类数 | 均匀抽类主门质量 | 相同 Z 下顺序概率跨类不同的条目 |
|---|---:|---:|---:|---:|
| CIFAR-10 | 1,010 | 1／1 | 0.09901% | 0 |
| CIFAR-100 | 10,100 | 3／3 | 0.02970% | 0 |
| ImageNet | 101,000 | 10／10 | 0.009901% | 7，即 0.006931% |

这里 Z 固定几何操作、带符号幅度和图像尺寸；两个分支对同一图像保留完全相同的源像素变换。令 `q = P(Invert 在几何之后 | class, Z, 主门事件)`。Identity 的位置不改变该定义。由源码可知各类幅度／符号的条件分布相同。

| 策略 | Z 的几何类型 | 原生类 ID 与 q | 支持判断 |
|---|---|---|---|
| CIFAR-10 | Rotate | 8:0 | 只有一类，无跨类共同支持 |
| CIFAR-100 | Rotate | 8:0 | 只有一类 |
| CIFAR-100 | TranslateX | 39:1，81:1 | 有共同几何支持，但 q 不变 |
| ImageNet | Rotate | 8:0，675:0 | q 不变 |
| ImageNet | TranslateY | 143:1 | 只有一类 |
| ImageNet | TranslateX | 39:1，81:1，421:0，892:0 | 操作／幅度层面有跨类条件差异 |
| ImageNet | ShearX | 394:0，586:0，795:1 | 操作／幅度层面有跨类条件差异 |

所有这些类在给定 Z 的主门中均只有一个原生方向，**没有同类两个方向的原生支持**。这不禁止以后定义新的随机干预，但干预方向会超出该类发布策略中的观测支持，不能称为“只重采样原有两种方向”。ImageNet 原始尺寸、图像内容与后续裁剪的联合支持没有下载数据核实；完整 Z 的经验共同支持仍未验证。

14 个数据集内主门条目全部位于各自列表的 index 1，明细原样保留在 `results/conditional-support.json`，没有按结果挑类。它们在数据集之间存在个别重复三元组，但完整类策略列表并不相同。

较宽的“含 Invert 与至少一个几何操作”集合分别有 10、237、3,474 条目，涉及 8、83、933 类。它们包含多几何操作或其他光度操作，不能用这些大分母替代窄主门事件频率。全部原生相关三元组共 119 种，枚举了 161 个位置交换。

## 3. 完整链像素与边界结果

协议及脚本在运行前写定并哈希冻结，见 `protocol-freeze.json`。总计 800 个基础操作检查、3,584 个完整链测试；核心像素审计 2.095 秒。载体固定为常色、有限范围渐变、全范围图、固定种子噪声。主门 9 种三元组 × 32 个参数情形 × 4 个载体；其余交换采用预定的 4 个参数情形作边界／反例检查。

| 测试集合 | 只改变几何补边且有非零变化 | 无变化 | 源／非补边像素改变 | 源映射／通道 mask 改变 |
|---|---:|---:|---:|---:|
| 主门 1,152 例 | 1,032 | 120 | 0 | 0 |
| 其他完整链 2,432 例 | 1,578 | 276 | 466 | 112 |

主门所有源像素最大绝对误差为 0。120 个无变化例没有当成有作用干预通过。800 个基础检查没有违反 nearest 有效区恒等关系；零几何变化单独记为 `no_delta`。这些比例是固定测试格点的结果，不能当作概率估计。

完整链反例包括原生 **相邻 Invert／几何交换后仍接其他操作**，不是仅靠跨过中间操作制造失败：

| 原生链 | 交换位置 | 16 个预定测试中的非补边失败数 | 最大源像素误差 |
|---|---|---:|---:|
| Invert → ShearX → Sharpness | 前两项 | 12 | 72 |
| Invert → TranslateY → Equalize | 前两项 | 16 | 255 |
| Rotate → Invert → AutoContrast | 前两项 | 12 | 255 |
| Rotate → Invert → Contrast | 前两项 | 16 | 36 |

其余非相邻交换、多几何、Cutout 顺序组合也完整保留，不能因某几个载体通过而把它们纳入主门。固定 1 灰度级容差另列在原始结果，未用来覆盖严格失败。

源像素 ID 与独立通道 mask 全程追踪；不把被后续全局统计／空间滤波影响的源像素从验证区域删掉。所有 **974 个未通过严格“非零且仅几何补边变化”条件的例子**（含无变化）均有 JSON 记录及 NPZ 数组归档，无删除失败样本。

### 后处理不是纯补边保证

作者 CIFAR 链在类策略之后执行 crop、flip、tensor/normalize、Cutout；ImageNet 在类策略后执行 crop、**bicubic** resize、flip 等，见 `dataset.py:247–253,1311–1338`、`data.py:66–76`。

固定 case 0／渐变载体的主门后处理示例：

- 27 个配对 CIFAR crop/flip/Cutout-mask 示例：25 个仍有纯几何补边差异，2 个差异被裁剪／遮挡消除，非补边差异均为 0。这里只验证像素 gather 与相同遮挡 mask；展示用 RGB 置零不等于复现归一化后 Cutout 的数值背景。
- 18 个 ImageNet 风格 crop/bicubic 示例：纯源核支持区域全部相同；14 个例子出现源／补边混合边界变化，4 个差异被裁掉。依据 Pillow float32 非零 bicubic 系数核的保守支持划分纯源、纯补边、混合区域，不把混合区域伪称纯补边。
- 因此严格的“网络输入上只有纯补边像素改变”对这 14 个缩放例不成立；若以后把混合带纳入处理通道，必须另定义估计目标。原生训练裁剪分布下的保留率未测。

补边形状始终可能透露几何操作。此干预最多隔离局部颜色／边界处理通道，没有去除形状、幅度、类别语义变换等信息。

## 4. 严重度门：未通过

事先定义全图严重度为输出对原始载体的平方 L2，要求两分支整数 SSE 完全相同。**1,032 个主门非零干预中，0 个满足；四种载体各 258 个非零例全部不满足。** 有效源像素和补边面积相同，不等于全图严重度相同。120 个无变化例的 SSE 相同不能挽救此门。

对于纯黑／纯白补边，设 F 为相同补边位置和通道，原图像素为 x，则

`SSE(white) − SSE(black) = Σ_F [(255−x)²−x²] = 255 Σ_F (255−2x)`。

只有 F 上原始像素通道均值恰为 127.5 时该差值为零，因此不能把有效区恒等直接当成严重度匹配。这个条件不是对所有可能图像的不可能性证明；本次预定载体没有满足它。未修改 fill、筛图、重加权或提高事件频率来迫使通过。感知严重度没有模型或经验验证，标为未验证。

## 5. 科学判断与下一道门

| 验收项 | 结果 | 含义 |
|---|---|---|
| 原生三元组、存储顺序、参数规则 | PASS（固定发布版本） | 是真实发布策略中的局部机制 |
| 主门 nearest 三元组源像素恒等 | PASS（当前 Pillow） | 不能泛化到完整任意链或历史依赖版本 |
| CIFAR 的同 Z 跨类顺序差异 | FAIL（该窄机制） | 不能用其作为原生 CIFAR 条件去关联实验 |
| ImageNet 的操作／幅度级跨类支持 | 部分 PASS | 7 条；类内双方向缺失；实际尺寸／裁剪联合支持未验证 |
| 最终输入仅纯补边变化 | 未全部通过 | bicubic 混合带会改变；经验保留率未知 |
| 预定逐样本全图 L2 严重度相等 | FAIL | 所有非零主门测试不相等 |
| 原生 clean 泛化损害、干预收益、创新性 | UNVERIFIED | 没有对应实验；已知前作限制泛泛主张 |

**当前建议：停在 CPU 先决门，不自动启动小训练。** 保留这个局部可识别性结果供 Pro 复核；不扩大主门、不挑类、不加密可干预事件、不重开旧封存测试。若后续仍要推进，先明确是否能接受并识别边界混合和严重度变化，核实完整 Z 的共同支持并按真实稀有频率做成本／精度评估，之后才另定方案。

候选两臂只能是原生顺序分布与条件去关联分布，须保持 Z、事件率及条件边际，而不是全局黑白数量匹配或固定标签置换。固定标签置换仍可能可解码。只有在前述障碍得到科学上明确的处理后，方案才应同时预注册：**两臂定向补边依赖差**与**独立 clean 错误率损害**。单纯载体解码、顺序指纹或敏感性均不足以构成所需贡献。本审计没有执行或批准该训练。

先行工作与完整固定源见 `SOURCE_LEDGER.md`。Kurakin 的标签扰动捷径、Visual Chirality 的非交换／载体／边界控制、Bayar/Stamm 的顺序指纹，以及 CAMEL、InstaAug 的条件增强，均已约束可声称的新颖性。CAAP 的 ECG／时间序列工作没有被当成图像方法证据。
