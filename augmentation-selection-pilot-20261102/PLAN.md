# EuroSAT / frozen DINOv2-Small augmentation-selection pilot

Authorized 2026-11-02. Task clock starts 04:20 UTC, hard end 06:20 UTC. Existing assets/environment only; CPU (MPS unavailable), 4 Torch threads/1 interop, <=12 GiB RSS, <=500 MiB new artifacts. No installation, downloads, uploads, cloud, CU or encoder training. Previous studies and slides remain unchanged.

1. Verify official EuroSAT ZIP hash, all ten classes and existing identity/split manifest; verify local DINOv2 safetensors/config identities. Use the historical 100/class trainpool and sample query images only from historical 300/class test. These pixels are exploratory, not fresh confirmation; filename/content disjointness does not establish geographic independence.
2. Freeze twelve per-class hash-ranked nested support sets B=8 subset B=16, four class-balanced folds by support rank mod4, and a fixed query list of 100/class. All views of an original stay in one fold. Support overlap across episodes is allowed and reported. Cache shared support features by original identity to save cost, not by effects.
3. Three policies: clean deterministic Resize256/CenterCrop224; weak RRC224 scale(.5,1) ratio(.75,4/3) bicubic plus horizontal flip(.5); the same weak view plus torchvision RandAugment(N=2,M=9,31bins,bilinear,RGB fill124/116/104). Normalize ImageNet means/stds. Each original has four training views; clean's identical four are represented without redundant encoder calls. Weak and RA share the exact geometry seed; RA has a separate per-original/view RNG stream. Validation/query always clean.
4. Frozen final normalized CLS384 features, unit-L2 per view. Deterministic float64 ridge: mean over originals of mean squared one-hot residual over four views + lambda=.001 times ||W||²; intercept unpenalized, train-only weighted centering. Each original has equal total loss weight. Fixed regularization, no search.
5. Four-fold CV selects by pooled original-image correct count. Exact ties prefer clean, then weak, then RA. Fit all three full-label heads regardless of CV, totaling 12*2*3*(4+1)=360 heads. Seal every head and all 24 selections before query feature extraction or query evaluation. No extra selected-head refit is necessary.
6. First run synthetic tests for ridge objective/weighting, duplicate-view equivalence, train-only centering, fold grouping and tie rule. Time a small fixed support-only CPU encoder batch and synthetic head solves without classification utility. Use a conservative complete-cost projection before full extraction. If needed before any query utility, reduce only query images/class via 100->50->25, preserving all budgets, episodes and policies; otherwise stop. Shared support caching is planned from the start.
7. Evaluate all 360 heads on the same query set after the seal. Primary: full-fit selected-minus-weak and selected-minus-RA paired accuracy changes, both budgets; show all fixed policies, all episodes, selection and harmful-selection counts. Post-hoc oracle regret, CV-vs-fold-query and fold-query-vs-full-query ranking comparisons are descriptive diagnostics, not deployable selectors or causal decomposition. No arbitrary pp success threshold, no effect-based stopping or modifications.
8. Persist protocol, identities, exact implementation/environment hashes, tests, feature cache, fitted heads, CV original-image predictions, all query predictions/scores, results and resource receipts; archive a new project directory. Assess whether any strategy differences/structure merit a separate encoder/dataset check, without claiming novelty or automatically running it.
