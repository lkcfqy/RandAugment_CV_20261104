# base 学习异常：训练侧短程诊断

结论：已重现并定位到**本次训练配方下可复现、对后端数值差异敏感的优化轨迹**。MPS 支路出现更严重的末层 ReLU 激活稀疏化和表征收缩，输出逐渐主要由分类头偏置决定。未发现图像—标签错配、模型/优化器错绑、BN 模式遗漏、梯度未计算或参数没有更新的证据。**这不能作为 TA 有益的证据；也尚不能把根因唯一归于 MPS 内核、学习率或固定 BN。**

本轮只是训练能力诊断，没有提出或验证新的数据增强贡献。未读取任何留出/开发评价图像。

## 实际执行和复现

- 仅使用原有 64 张训练照片，猫/狗各 32 张，保持原初始化、输入、样本顺序、SGD 配方、固定 BN running statistics 和可训练 BN affine。
- CPU 和 MPS 各重放 64 步、batch8；另外每设备各做 2 次隔离的“同一状态、同一输入”诊断更新。未跑完整 2048 步训练，未调整超参数。
- **两条轨迹各自的前 64 步 loss 与对应旧记录逐项完全相等，最大差为 0。** 当前 CPU 使用 deterministic=False，而旧 CPU 是 True；仍精确复现，因此该开关不足以解释此次早期分叉。
- 单进程、CPU 单线程、nice 增加 10、无数据加载 workers；主程序实测 32.403 秒，进程峰值 RSS 1,942,978,560 字节。含诊断统计的主训练计算为 CPU18.136 秒、MPS4.111 秒；这些不是新的性能基准。
- 本轮全部计算已结束。未运行 A100、远程 GPU、ARIS、新下载、依赖安装或升级，也未访问或修改 8A 项目文件。

## 哪一部分失效

以下都是同一批 64 张**训练图像**的结果，不能解释为泛化性能：

| 状态 | 干净训练交叉熵 | 准确率 | 512 维池化特征中，至少在一张图上非零的通道数 | 各通道跨样本方差的均值 |
|---|---:|---:|---:|---:|
| 共同初始状态 | 0.621023 | 59.375% | 512 | 0.635651 |
| CPU 第24步 | 0.082193 | 96.875% | 512 | 0.286355 |
| MPS 第24步 | 0.681979 | 85.938% | 512 | 0.482442 |
| CPU 第48步 | 0.819609 | 50.000% | 454 | 0.00772580 |
| MPS 第48步 | 0.712973 | 50.000% | 19 | 0.0000258654 |
| CPU 第64步 | 0.635979 | 73.438% | 298 | 0.00136526 |
| MPS 第64步 | 0.693073 | 50.000% | 18 | 0.00000159300 |

MPS 第64步的跨样本方差约为初始的 1/399,027，也是同一步 CPU 的约 1/857。97.592% 的池化特征元素为精确零；分类头权重仍非零（L2=1.81263），logits 与分类头偏置的最大差仅 0.003203。不是单纯把分类头置零。

固定首 8 张训练图上的末块最终残差 ReLU 输入，正值比例由初始 **56.8150%** 降至第64步 **0.1061%**，均值由 +0.45248 变为 −17.22929；对应 ReLU 输出大面积为零。较早层仍有非零输出。这为末层激活稀疏化提供了直接证据。

必须保留两个边界：

1. CPU 支路也经历明显收缩，第48步同样降到 50%，随后第64步回到 73.438%；旧 CPU 第128步训练准确率为 100%。因此收缩并非 MPS 独有，也不等于不可恢复。
2. MPS 第64步仍有 64 个不同的特征向量和 logits，没有一张图的整个 512 维特征全为零。**不能把这一早期近似塌缩直接等同于旧第2048步的恒定 logits，更不能声称已经证明原第2048步特征全零。**

## 已排除或明显削弱的解释

- **数据/预处理错误：**64 个标签均与官方完整 metadata 中相同 ID 的 species 一致；32/32 平衡。全部 base RGB hash 与旧记录一致；显式 resize256/center-crop224/ImageNet 标准化与安装版本官方 ResNet18 V1 transforms 的张量最大差为 0。预堆叠索引和逐图重建输入完全相同；图像与标签使用相同 ids。此处是历史定义的自定训练子集，并非官方 trainval-only 划分。
- **遗漏训练或优化器不更新：**全部参数都在优化器中、可训练且不重复；每步均有有限梯度，无缺失梯度；所跟踪的 conv1、末块 BN affine 和分类头每步都发生实际更新。手算 SGD 与实际参数的最大差为 CPU5.96e-8、MPS0（所跟踪参数）；有限性不代表训练稳定。
- **BN 模式错误：**模型处于 train，所有 BN 处于 eval；每次训练侧探针之后恢复同一设置。running statistics hash 前后完全一致，affine 仍按原配方训练。该配方是否适合本任务与模式是否实现正确是两个问题。
- **双模型交错/共享对象：**静态检查未见错绑；之前单独运行的 TA 前128步及 clean 预测与交错 recovery 完全相同。当前单臂 CPU/MPS 重放又分别复现了各自旧轨迹，不支持交错运行是此次异常的必要条件。
- **仅 MPS 推理算错：**把本轮 MPS 第64步的同一权重移到 CPU，交叉熵仍为0.693073、准确率仍50%，logits 最大差仅1.86e-8；把 CPU 第64步权重移到 MPS，仍为73.438%，logits 最大差4.92e-7。因此早期失效已存在于训练得到的参数状态，而非只在 MPS 前向显示中出现。

## 同状态反向与更新核对

在初始状态及 MPS 第24步状态，各克隆出独立 CPU/MPS 模型和相同 momentum 缓冲，以相同下一批输入各做一次更新；不会修改主重放轨迹。

| 检查状态 | logits 最大绝对差 | 全参数梯度相对 L2 差 | 实际更新量最大差 |
|---|---:|---:|---:|
| 共同初始状态 | 2.15e-6 | 4.12e-4 | 3.35e-7 |
| 同一 MPS 第24步状态 | 1.43e-5 | 2.66e-6 | 2.98e-8 |

梯度比较在 CPU NumPy float64 中计算。训练 trace 中设备侧 FP32 梯度范数只是近似统计，不能用其细小跨设备差值判断内核异常。

小的同状态数值差异与后续轨迹大幅分叉并存，支持“这套优化配置对数值扰动敏感”的诊断；两处检查不能证明所有内核无误，也没有隔离哪一个设置引发了失稳。此前 8 图短基准的数值接近，不能保证较长训练轨迹接近。

## 剩余最小缺口与使用限制

**已经解决：**失效是否可重现、是否有真实特征载体、是否发生了梯度和参数更新、是否只属于某设备的前向计算，以及常见标签/预处理/模式错误。

**尚未解决：**哪个优化条件促成并维持这种收缩（步长与 momentum、使用固定 running statistics 时的表征漂移，或未隔离的后端细节）。当前实验没有独立改变这些因素，不能指定某一个为唯一根因。原2048步权重没有保存，不能回溯其最终层状态。本轮保留了两份新的64步权重，后续不必再重放这段诊断。

在这一缺口闭合前，旧 base/TA 的差异应标记为**训练配方不稳定、对照不具备解释力**，不能作为增强收益、泛化能力或因果机制的证据。本轮未开始参数搜索或后续训练。
