# Colab 换机使用说明（公开开发副本）

本文是面向新机器的使用说明，依据原项目记录的 Colab CLI 0.7.5 帮助与源码行为整理，已替换历史账号检查回执。新机器需要独立安装相应 CLI、完成自己的登录并检查当前权限。本文不证明新机器已登录、可分配 GPU 或已具备实验所需资源；示例未在新机器执行。

## 恢复 CLI 和实验输入

1. 将所需版本的 `colab` 放入当前机器的 `PATH`，用 `command -v colab` 和 `colab --help` 检查入口。若安装版本不同，先核对该版本帮助；不复用原机器的可执行文件绝对路径或登录凭据。
2. 按 CLI 的登录流程完成当前账号授权。原 0.7.5 记录中的 `colab auth` 用于 VM 内 GCP 授权，不用于修复 CLI 自身登录；以实际安装版本帮助为准。
3. 恢复所选实验的代码、输入数据、兼容 checkpoint 和依赖，再运行对应的合成测试或预检。原记录中 CIFAR-10/兼容 checkpoint 的缺项仍需按资源清单处理；CLI 可用不代表实验已经可运行。
4. 提交任务前检查 `colab sessions` 和 `colab usage`，为本次实验确定运行预算、脚本、输入及产物保存路径。不要将当时其他机器的会话或账号余额作为当前状态。

## 短时独立脚本入口

原 0.7.5 的 `run --help` 和安装源码记录支持以下形式：

```sh
colab run --gpu T4 --session independent-colab --timeout 600 /absolute/path/to/approved_probe.py
```

将脚本占位路径替换为当前机器上的实际脚本。参数须放在脚本路径前；示例中的 GPU 型号、脚本和 600 秒均需按具体实验确定。`--timeout` 的原版本默认值为 30 秒，它控制代码执行等待，不是计算额度的硬预算。

省略 `--keep` 时，该版本 CLI 会尝试释放运行时，但清理属于 best effort；运行后仍须用 `colab sessions` 和 `colab usage` 核实是否释放。历史帮助列出 T4/L4/G4/H100/A100，但本文未验证当前容量、账号资格或型号可分配性。

## 取回产物与释放运行时

原 0.7.5 的安装源码表明，`run` 本身不会自动下载任意实验产物。需要取回文件时，先确定输出交付方案；可采用以下显式流程：

```text
new → exec → download → stop
```

执行前查看当前版本的 `colab new --help`、`colab exec --help`、`colab download --help` 和 `colab stop --help`，明确目标文件和本地保存位置。先验证产物已经取回，再停止运行时，避免默认清理移除尚未下载的产物。

## 并行与验证边界

为每个独立实验选择不同的 session 名称，并保留对应代码版本、输入资源标识和结果校验信息。并行任务分别核实资源分配、产物下载和运行时释放；实际额度和授权由当前使用者在本机检查。

本文依据的是原版本 `commands/run.py`、`commands/session.py`、`commands/usage.py` 与 `consumption.py` 的记录，没有在本次整理中分配 VM、运行训练或测试 GPU。它属于重新整理的开发说明，不是原始执行回执，不应据此声明历史封存哈希或执行结果保持相同。
