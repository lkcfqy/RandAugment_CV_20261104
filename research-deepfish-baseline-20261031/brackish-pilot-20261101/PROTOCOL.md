# Brackish 固定普通适配先导

唯一问题：在第二数据源中，开发集 AP@100 选择固定 5 图普通适配，能否在随后日期隔离的确认子集保持收益。既有方法的有限外部先导，不提出增强、算法或论文贡献。

数据固定为官方 Brackish v4。支持池日期为 2019-02-20、02-21、02-22、02-26、03-06、03-07；开发 03-19、03-20；确认 03-21、03-25。同一相机，日期隔离不等于跨地点。覆盖外的两段尾部全部排除；保留覆盖声明内的空标注帧，不宣称已证明视觉无鱼。AAU 与一致的 COCO 为框来源，fish/small_fish 合并为 fish，其余类别不映射为鱼并保留原始来源；不混用 YOLO。原标注文件不改。

支持视频来自已核验的 7 个严格单鱼总框候选视频；排序键为 UTF-8 `brackish-pilot-20261101-v1|video_ID` 的 SHA256（同哈希按视频 ID）。视频内使用完整标注恰有一个鱼目标的候选帧，可包含非鱼原框。episode0 用 V0–V4，episode1 用 V2–V6；共享视频按有序候选帧的 1/4、3/4 位置取不同图，独有视频取中位索引。三共享视频都满足至少两个候选。两套各五视频、五图、五鱼框；共享视频不构成独立重复，未证明不同鱼身份。

开发／确认每视频按合格帧号均匀取最多八帧；索引为 `floor((j+.5)*n/m)`。固定为开发288图325鱼框（213无鱼标注图）、确认120图38鱼框（83无鱼标注图），不因稀疏而换图。两套支持共10图，与评估图不重叠。帧身份及全部源标签在 `SELECTION.json` 和 `SOURCE_ANNOTATION_PROVENANCE.json`。

现有 OpenCV FFmpeg CPU 顺序解码，decoder n−1 对应发布编号n；1920×1080 用 OpenCV INTER_CUBIC 缩为960×540，原框不缩放、不裁剪。418图无损PNG与源视频均有SHA；不声称与作者ffmpeg命令行逐像素复现。本地研究、不外发；保留CC BY-SA署名、变更说明与相同方式共享来源，原COCO MIT字段冲突未澄清。

A0/A1均复用既有A配置：同原始Swin-T、同完整初始化、同trainable/AdamW/LR/梯度裁剪、seed20261031、batch1、40轮×5=200更新，普通随机几何和Color1恒等，最后完整checkpoint。无scheduler对象；每更新核恒定LR，不能根据loss或dev选步数。两臂每图恰40次曝光。模型、optimizer、Python/NumPy/Torch初始状态与历史CPU A核验。未适配P0使用同一完整初始化：900个原权重张量+7个固定exp(0)尺度+种子固定的训练专用DN状态；后者在推理中必须不调用，不能描述成原903键直接strict加载908键。

CPU FP32，Torch4线程、interop1、OpenCV顺序；官方现有库和权重pin不变，weights_only加载、无unsafe fallback。正式两模型完整安全落盘后，才推理开发集全三模型并统一算12指标。每episode各自A的dev主AP严格大于P0才选A，tie选P0，不在A0/A1之间选赢家。决定保存并hash后，确认集全三模型各做一次完整推理；确认结果不反向改参数。主AP为maxDets100，AP50/AP75/尺度AP为1000，AR为100/300/1000及尺度1000。保留官方top300全部预测，不加分数阈值。对全部持久化预测和precision/recall/scores数组独立复算。

先对两个固定200步数据轨迹分别核追踪与未追踪的像素、GT和RNG完全一致，再取各自最早的最大面积正GT输入做一次完整预检更新。实际固定轨迹最大为750×1333；时间和RSS按理论800×1333面积上限计余量。每次预检在独立进程，结束即丢弃全部模型/optimizer/RNG；正式从原权重重新初始化。

资源门使用预检时间与历史最大A步耗时的较大值估计400更新，按面积上限放大；加1224次推理的历史最大前向耗时、两模型完整保存验证120秒、初始化/指标/落盘固定300秒，整体乘1.25并计入已用预检时间。RSS按1.25×（预检RSS×面积比例+700MiB完整安全读回）估计。两新完整checkpoint约1.38GB，另保留150MiB预测/其它产物和80MiB目录余量。仅三个门全部通过才开始正式训练。

从生命周期启动开始最多3小时，RSS不超过12GiB，全部旧研究与新增目录合计不超过12GiB；外层对子进程设总deadline，异常结束保留回执。禁止删除旧资产、缩U、换episode、调强度、补种子或另加帧救结果。无安装、上传、GPU/MPS/Colab或新CU。

准备中出现一次局部模块命名冲突，发生在数据参考生成的导入阶段、任何模型调用前；已用相同配置归一化函数解决，原失败日志保留。没有科学配置更改。
